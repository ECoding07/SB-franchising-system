### 7.1 Bug fixed — franchise issuance date

`issueFranchiseAction` computed the expiry with `dateIssued.setFullYear(...)`, which **mutates `dateIssued` in place**. The franchise was being recorded as issued on its *expiry* date. Now the expiry is computed on a separate `Date` value. Verified: issued `2026-09-29`, valid until `2028-09-28` — exactly the 2-year setting.

### 7.2 Staff access gate

The staff layout used `requireRole(["staff"])`, which locked out admins even though the admin role holds the `applications.review` permission. Changed to `requireAnyPermission(["applications.review"])`. Verified: admin → 200, staff → 200, operator → 307 to `/`.

### 7.3 Refactor for testability

Server Actions cannot be invoked over plain HTTP (`Error: Connection closed.` — the action protocol is not plain form POST), so business rules living inside `"use server"` files were untestable.

Extracted all review logic into **`src/lib/review.ts`** — plain async functions taking an explicit actor, independent of the Next request context. `(staff)/actions.ts` is now thin: `requireUser()` → call service → `revalidatePath()`. Supporting split: `SessionUser` moved to `auth/session-types.ts` and `hasPermission` to `auth/permissions.ts`, so the service layer does not pull in `next/navigation`.

## 11. Lessons learned (added to the running list)

1. **`setFullYear` mutates the receiver.** Any date arithmetic that "derives" a second date from a first one must not reuse the original `Date` object. This bug silently recorded a 2-year-old issue date and was only caught by asserting on the persisted values, not by reading the code.
2. **Keep business rules out of `"use server"` files.** Server Actions are the auth/transport layer. Rules there are untestable (the action protocol is not plain HTTP) and hard to reuse from the mobile app.
3. **Role-based guards hide permission bugs.** `requireRole(["staff"])` and a permission-based page looked equivalent but disagreed about admins. Guard the layout with the same permission the page actually requires.
4. **A passing test can be testing the wrong thing.** Assert on the specific error message, not just "it returned an error" — otherwise an early validation branch makes an unrelated assertion look green.
5. **Renaming a route early is cheaper than a collision later.** `/applications` was needed by both the operator detail page and the staff queue; route groups make both exist simultaneously but URLs must stay distinct.
6. **Verify against persisted data, not return values.** Reading a `Date` variable in memory looks right even when the write path mutates it before serialization.
7. **Two identical doc files will happen.** A copy at the repo root and one in the app's `docs/` differed by nothing at all. Check hashes before committing both.
8. **`git push` can hang silently on Windows.** Git Credential Manager may wait on a dialog the shell cannot display. Run the push backgrounded, redirect output to a file, then poll the log and `rev-list --count` to confirm.
