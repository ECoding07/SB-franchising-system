**Honest findings recorded for the docs (remediation, not yet fixed):**

- **A — RLS is defense-in-depth only.** Migration header (`rls_defense_in_depth/migration.sql:3-6`) states the Prisma role owns the tables and bypasses RLS; application authorization lives in the API layer. The paper's "RLS prevents UI bypass" claim is not true as built. **R1:** create a non-owner Postgres role so RLS is genuinely enforced.
- **B — `franchise.view_all` granted to operators** (`prisma/seed.ts:82`) contradicts own-records-only; never checked anywhere in `src/`. **R2:** add `franchise.view_own`, remove `view_all` from operator, re-seed.
- **C — Email specced, not installed.** `SMTP_*` empty, no Nodemailer dependency (`package.json`). **R3:** install Nodemailer + configure Supabase SMTP.
- **R4:** email confirmation is not a real gate — `(auth)/actions.ts:97` syncs an active `operator` user before confirmation; `session.ts:35` has no lazy sync. (This is Phase 6.0.)
