## 10. Lessons learned / pitfalls (worth keeping)

1. **Never `npm install react-native@latest` on Expo.** Template pins are authoritative (`react-native 0.86.3`); latest (0.87.1) is incompatible with the SDK. Same rule for React version. Always reconcile via `npx expo install` / `expo-doctor`.
2. **Expo + Tailwind v4**: NativeWind does not support Tailwind v4 in a stable release; don't burn time — pick a component kit (React Native Paper) or wait for NativeWind v5 RC.
3. **Prisma 7 changed the model:** needs a driver adapter (`PrismaPg`) at runtime, `prisma.config.ts` (URLs no longer in `schema.prisma`), and the `prisma-client` generator **requires** an explicit `output` path. The generated client is a build artifact — gitignore it.
4. **Supabase RLS and UUID types:** `auth.uid()` returns `uuid`; comparing against `text` columns (uuid was modeled as String in Prisma) fails — cast with `auth.uid()::text`.
5. **UTF-8 BOM breaks `prisma migrate deploy`.** A file saved with a BOM fails to apply. Rewrite any touched migration file without a BOM.
6. **Enum vs model name collision:** `UserRole` existed as both an enum and a model. Rename the enum (`RoleName`) before it bites later.
7. **Supabase direct host is IPv6-only here** — no global IPv6 on this Windows machine, so use the pooler (6543 runtime / 5432 migrations). Put `DIRECT_URL` in `prisma.config.ts`, not `DATABASE_URL`.
8. **Next.js 16 is not the familiar Next.js:** `middleware.ts` → `proxy.ts`; favor Server Actions + `useActionState` for auth. Read the bundled docs in `node_modules/next/dist/docs/` before coding.
9. **Next + Turbopack on Windows:** a lockfile in a parent directory can confuse Turbopack → pin `turbopack.root` in `next.config.ts`.
10. **RLS is defense-in-depth, not the app's ACL:** the Prisma connection role bypasses RLS (table owner). Authorize in the app layer anyway; RLS protects direct table access from other roles (anon/authenticated) and future non-owner DB roles.
